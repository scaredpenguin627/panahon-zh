# panahon-zh 产品范围矩阵与前端重做边界（阶段 3）

本报告依据以下两份报告归一化整理：

- docs/huawei-weather-video-observation-report.md：阶段 1 视频事实，保留已观察、推断、未知标签。
- docs/panahon-zh-project-inventory-stage2.md：阶段 2 源码与验证状态，保留已实现、部分实现、仅计划、未发现、未验证状态。

本报告只决定产品范围，不删除或改写阶段 1、阶段 2 报告中的事实。Cargo 缺失导致的项目状态继续写为未验证，不写成 Rust 代码失败。

目标动作含义：保留=继续使用现有功能和数据基础；替换 UI=保留数据和业务逻辑并重做 Rust/egui 呈现；扩展=已有部分能力并补足观察到的行为；先修复=当前实现可能造成错误或误导；暂缓=需要数据、平台能力或原型验证；排除=属于华为账号、系统服务、专有平台或当前项目范围之外；未知=证据不足，暂不决定。

## 二、七项数据可信度门槛

| 门槛 | 阶段 2 当前状态 | 阶段 3 决策 | 验收条件 |
|---|---|---|---|
| 1. 缺少降水不得显示为 0 mm | 部分实现，P0 先修复。core/src/lib.rs 缺失时写入 0.0 和 Unavailable；src/widgets.rs 多处会隐藏，但新 UI 仍可能误读内部哨兵值 | 所有页面和数据绑定先判断质量 | current、hour、day 缺失时永不渲染 0 mm；真实 0 才显示 0.0 mm，并带来源和时间 |
| 2. 官方热指数与本地估算必须区分 | 基本已实现，仍需运行验证。官方观测为 Official，nowcast 为 Forecast，估算为 Estimated | 保留数据模型，补齐 UI 标签 | 每个热指数显示 Official、Forecast、Estimated 或 Unavailable；估算不得写成官方 |
| 3. 日期使用 Manila 时区和带时区时间 | 已实现，仍需运行验证。core/src/trust.rs 有 UTC+8、跨年和非法日期测试 | 保留规则，不在 UI 层重写 | UTC 跨日、RFC3339 偏移、跨年日期均稳定；日期和时间显示依据明确 |
| 4. 未知天气图标必须明确显示未知 | 部分实现，P0 先修复。WeatherIcon::Unknown 存在，但 src/icons.rs 默认分支可能绘制成云雨 | 增加专用未知图标和文字 | 未知输入显示未知或 Unknown 专用图形，不得伪装成普通天气 |
| 5. 生活指数只在输入完整时显示 | 未满足，P0 先修复。life_indices 只有有限当前值，部分指数固定不可用 | 每项指数声明所需小时/日字段和质量 | 缺少必要字段时显示暂无指数和原因；完整输入时显示依据、质量和更新时间 |
| 6. 每个数值有来源、更新时间或不可用原因 | 部分实现，P0 补强。天气、AQI、日照有部分来源字段和 badge；湿度、风、地图、预警、生活指数粒度不足 | 引入统一 view-model 展示层 | 每个数值或图层有来源和时间，或明确的 Unavailable 原因 |
| 7. 地图、AQI、预警、生活指数有明确质量状态 | 部分实现，P0 补强。AQI 有部分来源/时间；RemoteMapSnapshot、Alert 和部分生活指数缺统一质量字段 | 补齐跨域质量和失败状态 | 地图帧、AQI 摘要/站点/趋势、预警、生活指数都显示官方、模型、估算、不可用或失败原因 |

## 四、证据冲突和未决问题

1. 视频观察到、当前项目没有：15/90 日预报、月度视图、霞光地图、月相、健康页、内嵌天气视频、桌面向导、资源下载、空间感天气、服务模式和 Huawei 条款页。
2. 当前项目有、视频未观察到：PAGASA/Open-Meteo/EMB/CAMS 数据适配器、DataSource、DataQuality、Android weather_cache_v2、AQI 48 点历史、中文/English 切换。
3. roadmap 与源码不一致：roadmap 仍将预警地点过滤、AQI 历史等列为下一步，但源码已经有部分或完整实现；应以源码和当前验证结果为准。
4. 功能存在但数据不足以安全展示：缺失降水使用内部 0.0 哨兵值；未知图标可能伪装成普通云雨；地图、预警、生活指数缺统一质量字段；AQI 上游本轮请求超时。
5. 只有系统或 Huawei 专有服务才能完成：系统桌面小组件、Huawei 推送、Huawei 账号、云空间、服务条款、空间感资源和专有天气视频。

7. 环境限制：rustc 和 cargo 未安装，因此 Rust 构建、测试和联网示例保持未验证，不能写成 Rust 失败。

## 五、推荐的首批范围和取舍

建议第一阶段只做一条完整闭环：

天气首页 → 逐小时/五日预报 → AQI 摘要与污染物 → 核心天气地图 → 预警与原文复制 → 设置/中文 English/来源/更新时间/错误状态。

取舍理由：

- 这些功能已有相对明确的数据模型和适配器；
- 能形成首页、AQI、地图、预警之间的完整进入和返回路径；
- 可以集中修复七项数据可信度门槛；
- 不依赖 Huawei 账号、系统桌面或专有资源；
- 不把视频中无法确认的数据功能硬塞进首批范围；
- 先稳定质量、缺失状态和来源信息，再增加动画和扩展入口。

## 六、前端重做边界

### 应保留

- Dashboard、AirQuality、Alert、RemoteMapSnapshot、LifeIndex 等数据模型；
- DataSource、DataQuality、来源、更新时间和不可用原因逻辑；
- Manila 时区、日期、热指数、降水缺失、观测新鲜度和预警过滤；
- PAGASA、Open-Meteo、EMB、CAMS 和地图数据适配器；
- Power BI DSR 解码和 Node AQI JSON 契约；
- clean-room 约束以及原创图标和资源边界。

### 可以替换或重组

- src/app.rs 页面组合、导航栈和交互编排；
- src/widgets.rs 卡片、列表、图表和导航视觉；
- src/theme.rs 颜色、天空背景、圆角、间距和动效参数；
- src/icons.rs 图标的视觉呈现，特别是 Unknown 状态；
- PanahonApp 中网络消息、缓存、页面状态和 UI 事件的耦合；
- 新增 view-model adapter，将 core 数据转换成页面可消费的状态；
- 将加载、错误、缓存、来源和质量状态作为统一 UI 状态。

建议的数据流：

PAGASA / Open-Meteo / EMB / CAMS / Node AQI
                ↓
core 数据模型 + trust/source/quality
                ↓
view-model adapter
                ↓
Rust/egui 页面、卡片、地图、设置

新 UI 不应直接读取原始 JSON，也不应重新实现降水缺失、热指数来源、Manila 日期、预警范围或 AQI 来源判断。
